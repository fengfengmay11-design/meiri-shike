# 食刻推荐引擎算法文档

本文档说明「食刻」智能选餐助手的推荐算法设计，包括打分模型、过滤规则、可解释性生成三部分。

## 1. 问题定义

输入：用户的身心状态（8 种预置 + 1 种自定义）、饮食偏好（菜系/主食/水果）、忌口清单（口味/蔬菜/水果）、就餐位置（学校/公司 + 校区/分部）

输出：差异化的三餐方案（早餐/午餐/晚餐），每餐包含招牌菜、主食、配菜、水果、总热量、推荐理由、可解释打分链

约束：
- 总热量落在状态对应区间（如减脂期 480-650 kcal/餐）
- 不触碰任何忌口项
- 三餐菜系不重复
- 偏好菜系抽中概率提升

## 2. 打分模型

### 2.1 状态配置（STATUS）

每种状态定义一组推荐参数：

| 状态 | 热量区间 | 特殊规则 |
|------|----------|----------|
| 正常 | 600-800 | 无 |
| 学习备考 | 550-700 | 蛋白质加权（防犯困） |
| 运动减脂 | 480-650 | 蛋白质加权 + 低糖水果 |
| 熬夜加班 | 550-700 | 忌辣 + 忌油腻 |
| 健身增肌 | 700-920 | 蛋白质加权 + 额外加菜 |
| 控糖控重 | 450-600 | 低糖水果 + 低卡加权 |
| 生理期 | 500-650 | 温热软食 |
| 疾病修养 | 450-600 | 软烂 + 忌生冷 + 忌辣油 |

### 2.2 菜系抽取（加权随机）

```
权重 = 1（基础）
     + 2（命中用户偏好菜系）
     + 1（菜系内有菜品命中自由文本偏好关键词）

从加权袋中不放回抽取 3 个不同菜系
若与上次推荐完全相同，重抽（最多 4 次）
```

### 2.3 菜品过滤链

每道候选菜按顺序经过：

1. **状态忌口**：当前状态 avoidSpicy → 排除 taste 含「辣」的菜；avoidOily → 排除「油腻」
2. **用户忌口**：avoidTaste/avoidVeg 清单逐项过滤（菜品的 taste 和 veg 字段匹配）
3. **特殊规则**：noRaw（疾病修养）→ 排除沙拉类
4. **兜底**：过滤后为空则回退到未过滤池（保证一定有推荐）

### 2.4 菜品打分与选定

```javascript
score(dish) =
  +8  if cfg.preferProtein && dish.protein     // 蛋白质需求
  +8  if cfg.preferLowKcal && dish.kcal < 120  // 低卡需求
  +5  if dish 命中自由文本偏好关键词           // 用户写的"想吃海鲜"
  -20 if dish 含状态忌口成分                   // 双保险
```

取打分最高者为主菜，次高为配菜；增肌状态额外加第三道。

### 2.5 热量校准

总热量超出状态区间时，在不破忌口前提下迭代调整：
- 超上限：按热量降序移除配菜（保留主菜）
- 低于下限：从候选池补充不超上限的菜

### 2.6 水果选择

- `fruitLow`（减脂/控糖）→ 选该菜系热量最低的水果
- 否则选第一个（各菜系预置的当季水果）

## 3. 推荐理由生成

三层叠加，保证每条理由个性化且不重复：

1. **菜品亮点**：命中招牌关键词（如「清蒸鲈鱼」→「刺少肉嫩」）
2. **状态理由**：该状态 6 条模板随机选（如减脂期「低卡高蛋白，吃饱不胖」）
3. **状态加成**：菜品命中状态关键词库（如减脂期命中「鸡胸/藜麦/沙拉」→ 追加「高蛋白低脂」）

## 4. 可解释性输出（explain）

每餐返回打分链，供前端展示「为什么推荐这道」：

```
[1] 状态匹配 — 当前状态「运动减脂」，热量目标 480-650 kcal
[2] 忌口过滤 — 按你的忌口设置过滤掉 3 道候选菜
[3] 忌口过滤 — 当前状态忌辣，已排除辣味菜品
[4] 偏好加权 — 你偏好的「川、粤」菜系抽中概率提升
[5] 营养加权 — 「鸡胸藜麦碗」富含蛋白质，符合当前状态需求
[6] 控糖选择 — 选择低糖水果「圣女果」（30 kcal）
[7] 最终选定 — 从 5 道候选中按打分选出「鸡胸藜麦碗」
```

## 5. 自然语言偏好提取（nlParser）

规则引擎（非 LLM，可平滑替换）：

- **触发词模式**：9 类忌口（不吃/讨厌/过敏/不能/不碰/戒/避开/反感/忌）、8 类偏好（喜欢/爱吃/爱/偏好/最爱/钟爱/常吃/痴迷）
- **并列拆分**：「辣和香菜」→ 先按连词拆分，再剥离填充字
- **同义词归一**：50+ 别名映射（日料→日式、芫荽→香菜、奇异果→猕猴桃）
- **分组归位**：提取词自动归入 profile 的 cuisine/staple/fruit/avoidTaste/avoidVeg/avoidFruit 六组

## 6. AI 营养师规则引擎（aiNutritionist）

意图识别 + 上下文感知的问答引擎，9 类意图：

| 意图 | 触发词 | 上下文使用 |
|------|--------|-----------|
| 推荐吃什么 | 吃什么/推荐 | 状态 + 偏好菜系 + 忌口过滤后抽菜 |
| 能不能吃X | 能吃/可以吃 | 忌口清单匹配 + 状态规则匹配 |
| 高蛋白 | 蛋白/增肌 | 全库 protein 标记菜 |
| 减脂 | 减脂/热量 | 状态热量区间 |
| 生病 | 感冒/不舒服 | 疾病修养状态建议 |
| 犯困 | 困/没精神 | 血糖管理建议 |
| 经期 | 经期/生理期 | 温补建议 + 状态切换引导 |
| 食堂 | 食堂/学校 | 当前位置信息 |
| 自我介绍 | 你是谁 | 功能说明 |

兜底：3 条上下文感知的通用回复随机选。

**LLM 接口位**：`aiNutritionist.answer()` 函数即替换点，将规则引擎换成大模型 API 调用即可，入参（status/profile/location）已结构化。

## 7. 食堂菜单融合

设置学校 + 校区后，推荐结果自动注入所选食堂的当日菜单（`injectCanteenDish`）：
- 菜单模板池按地区差异化（北方面食/川渝辣味/江南清淡）
- 命中食堂菜的餐标记来源「📍 来自 XX大学 XX校区 食堂今日菜单」

## 8. 局限与规划

| 当前局限 | 规划 |
|----------|------|
| 菜谱库 112 道，多样性有限 | 接入真实菜谱 API 或 LLM 生成 |
| AI 对话为规则引擎 | 替换为混元/GPT 函数调用 |
| 食堂菜单为模板模拟 | 学校后勤系统/众包菜单接入 |
| 无用户画像长期学习 | 推荐采纳率埋点 + 偏好在线学习 |
